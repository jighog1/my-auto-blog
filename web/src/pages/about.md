# AI 브리핑룸 소개

**AI 브리핑룸**은 바쁜 직장인이 AI 변화의 핵심을 빠르게 파악하고, 실제 업무에 적용할 판단 기준과 도구를 얻도록 돕는 개인 미디어 프로젝트입니다.

## 누구를 위한 글인가

1순위 독자는 업무에 AI를 적용하려는 직장인, 2순위 독자는 개발자와 IT 실무자입니다. 새로운 제품을 빠르게 소개하는 것보다 다음 질문에 답하는 글을 우선합니다.

- 공식 발표에서 실제로 확인된 내용은 무엇인가?
- 업무에 도입할 가치와 조건은 무엇인가?
- 지금 바로 사용할 수 있는 체크리스트나 템플릿은 무엇인가?
- 아직 확인되지 않았거나 직접 검증해야 할 부분은 무엇인가?

## 글을 만드는 방법

RSS에서 후보 주제를 찾은 뒤 검색 결과를 보조 자료로 사용합니다. 제품·프로젝트·연구의 직접 출처가 있고, 서로 다른 도메인의 출처를 두 곳 이상 확보한 주제만 발행 대상으로 삼습니다.

본문 초안에는 생성형 AI를 사용합니다. AI는 제공된 출처 밖의 사실을 단정하지 못하며, 핵심 사실 옆에 원문 링크를 연결해야 합니다. 발행 전에 다음 항목을 자동 검사합니다.

- 직접 출처 포함 여부와 출처 도메인 다양성
- 본문 속 원문 인용과 참고자료 일치 여부
- 최근 글과의 주제 중복
- 과장 표현, 허위 경험담, 확인되지 않은 수치
- 독자가 재사용할 수 있는 표·템플릿·체크리스트 포함 여부

자동 검사는 사람의 사실 확인이나 제품 사용 테스트를 대신하지 않습니다. 사람이 별도로 검토한 글은 본문 상단에 그 사실을 명시하며, 표시가 없다면 자동 검사를 통과한 AI 보조 작성물입니다.

## 발행하지 않는 경우

분량을 채우기 위한 반복 설명, 원문을 바꿔 쓴 요약, 검색 결과의 블로그·커뮤니티만으로 구성된 글은 발행하지 않습니다. 업무 관련성이 약하거나 직접 출처를 찾지 못한 날에는 새 글을 만들지 않습니다.

## 정정과 문의

중요한 결정을 내리기 전에는 각 글의 참고자료와 제품의 최신 공식 문서를 함께 확인해 주세요. 사실 오류, 끊어진 링크 또는 정정이 필요한 내용은 [GitHub Issues](https://github.com/jighog1/my-auto-blog/issues)에 남길 수 있습니다.

운영 코드와 자동 품질 정책은 [GitHub 저장소](https://github.com/jighog1/my-auto-blog)에서 공개합니다.
