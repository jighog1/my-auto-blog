## 실무 판단

### 판단 1. 안전성 주장은 통제권의 문제로 다시 읽어야 한다

편집부의 해석으로, 이번 논쟁에서 가장 중요한 질문은 ‘누가 안전한가’가 아니라 ‘누가 안전의 기준과 예외를 정하는가’입니다. 특정 연구소가 위험을 평가하고, 공개 범위를 정하고, 사고를 조사하고, 규제 완화까지 요구한다면 안전 전문성은 높을 수 있어도 권한이 한곳에 집중될 수 있습니다.

기업의 AI 도입에서도 같은 구조가 반복됩니다. 공급자가 “이 모델은 안전하다”고 말하는 것만으로는 충분하지 않습니다. 기업 내부에서 모델을 승인한 조직이 동시에 사고를 조사하고 사용 중단 여부까지 결정한다면, 편의성과 책임 회피가 충돌할 수 있습니다. 모델 공급자의 안전 문서와 별개로, 사용 기업이 독립적으로 로그를 확인하고 권한을 회수할 수 있는지가 핵심입니다.

### 판단 2. 오픈 웨이트 논쟁은 공개·비공개 중 하나를 고르는 문제가 아니다

오픈 웨이트에는 검증 가능성이라는 이점과 악용 가능성이라는 위험이 함께 있을 수 있습니다. 따라서 실무에서 단순히 ‘공개 모델은 위험하다’ 또는 ‘공개 모델이 더 신뢰할 만하다’고 결론 내리기보다, 사용 목적과 통제 수준을 조합해야 합니다.

예를 들어 사내 문서 요약과 코드 초안 작성은 외부 도구의 접근 권한, 데이터 보존, 감사 로그가 더 직접적인 위험 요소일 수 있습니다. 반면 생명과학, 사이버보안, 자동화된 외부 시스템 조작처럼 결과가 즉시 현실에 영향을 주는 업무라면 모델의 공개 여부만이 아니라 도구 호출 권한, 승인 절차, 출력 검토가 중요합니다.

### 판단 3. 미래 성능보다 현재의 책임 구조를 먼저 평가해야 한다

질병 치료나 생산성 향상에 대한 장기 전망은 조직의 투자 방향을 검토할 때 참고할 수 있습니다. 그러나 단기 도입 결정을 정당화하는 근거로 사용하기에는 불충분합니다. 실무자는 ‘언젠가 큰 이익을 줄 것’이라는 서사와 ‘이번 분기에 어떤 위험을 누가 관리할 것인가’라는 운영 질문을 분리해야 합니다.

이 관점에서 가장 유용한 평가 지표는 모델의 벤치마크 점수 하나가 아닙니다. 승인되지 않은 데이터에 접근했을 때 탐지되는지, 잘못된 결과를 사람이 되돌릴 수 있는지, 사고 발생 시 공급자와 사용자의 책임 경계가 계약에 적혀 있는지, 서비스가 중단되어도 업무를 이어갈 대체 절차가 있는지가 더 실무적입니다.

### 2단계: 고위험 업무와 저위험 업무를 분리하기

첫 시도는 되돌리기 쉬운 업무로 제한하는 것이 좋습니다. 예를 들면 공개 자료를 바탕으로 한 초안 작성, 회의 내용의 구조화, 테스트 데이터에 대한 코드 설명처럼 결과를 사람이 검토하고 원상 복구할 수 있는 작업입니다.

반대로 인사 평가, 고객에게 자동 발송되는 법률·금융 안내, 운영 시스템의 직접 변경, 생명·안전과 연결된 판단은 별도 승인 없이는 자동화하지 않는 편이 안전합니다. 이 구분은 모델이 ‘똑똑한가’보다 오류가 발생했을 때 피해를 되돌릴 수 있는가를 기준으로 합니다.

### 3단계: 작은 파일럿을 운영하되 성공 조건과 중단 조건을 먼저 적기

파일럿 시작 전에 다음 네 가지를 문서로 고정하십시오.

1. **목표:** 처리 시간 단축인지, 초안 품질 개선인지, 검색 편의성 향상인지 한 가지로 좁힙니다.
2. **검토자:** 모델 결과를 승인할 사람과 최종 책임자를 분리해 지정합니다.
3. **기록:** 입력 유형, 출력 오류, 수정 시간, 권한 사용 내역을 기록합니다.
4. **중단 조건:** 민감정보 노출, 근거 없는 확정 표현, 승인 없는 외부 전송, 반복되는 치명적 오류가 나타나면 즉시 중단합니다.

파일럿 결과를 평가할 때는 “모델이 좋은 답을 몇 번 했는가”만 보지 말고, 사람이 오류를 발견하는 데 걸린 시간과 오류가 업무 흐름에 유입된 단계도 기록해야 합니다. 생산성이 높아 보여도 검수 비용이 더 커지면 도입 효과는 제한적입니다.

이 질문에 답하지 못하는 공급자는 성능이 높더라도 고위험 업무에 바로 투입하기 어렵습니다.
