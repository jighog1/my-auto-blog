## 업무에 어떻게 쓸까

팀이나 오픈소스 프로젝트의 AI 기여 정책을 검토할 때는 아래 순서로 시작할 수 있습니다.

1. **공식 문서에서 적용 대상을 확인합니다.** 행동강령, 기여 가이드, 저장소 공지 중 무엇이 규칙을 정하는지 확인합니다. 문서의 제목이나 논의 글만으로 조항을 추정하지 않습니다.
2. **작업 유형을 나눕니다.** 코드·테스트·문서 작성, 코드 설명, 자동완성, 오류 분석, 검토 의견 작성 등을 별도 항목으로 놓습니다. 실제 정책이 허용·제한·금지하는 범위를 각 항목에 표시합니다.
3. **제출 절차를 정합니다.** 공개가 필요한 경우 어떤 정보를, 어디에, 어느 시점에 적을지 정합니다. AI 사용 사실 공개만으로 검증 책임이 대체되지 않도록 합니다.
4. **검증 기준을 붙입니다.** 빌드와 테스트, 하드웨어 동작 확인, 변경 이유 설명 등 프로젝트에 필요한 증거를 지정합니다. 검증할 수 없는 변경은 병합을 보류하는 기준을 둡니다.
5. **한 건의 변경으로 시험합니다.** 실제 기여 요청이나 내부 코드 변경에 기준을 적용해 모호한 항목을 찾고, 정책 문구와 리뷰 양식을 보완합니다.

**적용 조건:** 기여 정책의 공식 문서와 유지관리 주체를 확인할 수 있고, 변경을 검증할 담당자와 절차가 있을 때 적용합니다.

**중단 조건:** 공식 조항이 확인되지 않거나 정책의 적용 저장소가 불분명한 경우, AI 사용 여부를 근거로 승인·거절하지 않습니다. 먼저 관리자에게 기준을 확인하고, 고위험 코드라면 검증 계획이 마련될 때까지 제출 또는 병합을 보류합니다.

바로 복사해 쓸 수 있는 검토 질문은 다음과 같습니다.

> - 코드 생성, 자동완성, 설명·검토 보조 중 무엇을 허용하는가?
> - 사용 사실을 공개해야 하는가? 공개 위치와 형식은 무엇인가?
> - 제출자가 직접 설명하고 검증해야 하는 범위는 어디까지인가?
> - 문구가 불명확할 때 누가 해석하고 예외를 승인하는가?
