## 실무 판단

편집부의 해석은 간단합니다. 검색을 모델에서 분리할 가치는 검색 단가가 낮아지는 데만 있지 않습니다. 여러 에이전트가 같은 정보를 찾는지, 특정 검색 업체의 장애나 가격 변경에 얼마나 민감한지, 모델 응답을 JSON·불리언처럼 엄격하게 파싱해야 하는지를 한곳에서 다룰 수 있다는 점이 운영상 중요합니다. 반대로 검색이 거의 반복되지 않거나 검색 공급자에 따라 결과 품질이 크게 달라지는 업무라면, 게이트웨이 개발·운영 부담이 절감액을 앞설 수 있습니다.

캐시는 정확도와 최신성 사이의 절충입니다. 반복 질문의 결과를 재사용하면 중복 호출을 줄일 수 있지만, 가격·재고·정책처럼 빠르게 바뀌는 자료에서는 오래된 결과가 잘못된 후속 결정을 만들 수 있습니다. 따라서 캐시 적용 여부는 ‘질문이 비슷한가’만으로 결정하지 말고, 결과가 유효한 시간과 자료의 변경 주기를 함께 고려해야 합니다. 캐시 적중률이 높아도 잘못된 결과를 재사용한다면 비용 절감은 성공으로 보기 어렵습니다.

또한 ‘정확도 유지’는 평가 대상이 무엇인지 확인해야 의미가 있습니다. DoorDash 사례의 보도 내용은 검색 의도 분류 등 특정 평가 결과를 말합니다. 최신 웹 사실, 검색 결과의 적합성, 최종 답변의 정확도, 파싱 성공률은 서로 다른 지표입니다. 검색 방식 변경을 승인할 때는 이 지표들을 묶어 하나의 정확도 숫자로 처리하지 않는 편이 안전합니다.

## 업무에 어떻게 쓸까

가장 현실적인 시작점은 검색이 포함된 업무 하나를 고르는 것입니다. 사내 정책 질의, 상품·문서 탐색, 고객 문의 분류처럼 검색어와 결과를 기록할 수 있고, 사람이 정답 여부를 판정할 수 있는 작업이 적합합니다. 처음부터 공통 플랫폼을 만들기보다, 기존 호출에서 어떤 질문이 반복되고 검색 결과가 어디에 쓰이는지 확인한 뒤 분리 범위를 정합니다.

1. **기준선 기록:** 일정 기간 질문, 검색 호출 횟수, 검색 비용, 응답 지연, 결과의 최신성, 최종 분류나 답변의 정답 여부를 모읍니다. 검색 비용과 모델 추론 비용은 별도 항목으로 집계합니다.
2. **반복성 확인:** 같은 질문과 의미가 비슷한 질문이 얼마나 자주 나오는지 살핍니다. 반복이 적다면 캐시 효과가 작을 수 있으므로 게이트웨이 개발보다 검색 설정 정리부터 검토합니다.
3. **작은 범위에 분리 적용:** 검색 요청과 결과 전달을 별도 인터페이스로 둡니다. 결과에는 최소한 제목, URL, 발췌문과 검색 시각을 넣고, 모델이 답변에 쓸 근거와 원문을 구분할 수 있게 합니다. 검색 공급자 교체를 쉽게 하려면 호출 형식과 오류 형식을 일정하게 유지합니다.
4. **캐시 조건 설정:** 자료 종류별로 유효 기간을 다르게 두고, 변동성이 큰 정보는 짧게 유지하거나 캐시하지 않습니다. 캐시된 결과인지와 검색 시각을 기록해 오래된 근거가 답변에 쓰였는지 추적합니다.
5. **기존 방식과 비교:** 동일한 질문 묶음으로 내장 검색과 게이트웨이를 비교합니다. 검색 의도 정확도뿐 아니라 최신성, 최종 답의 정확도, 출력 파싱 성공률, 검색 비용, 추론 비용, 지연시간을 함께 봅니다. 일부 질문은 최신 정보를 요구하도록 구성해야 검색 방식별 차이도 확인할 수 있습니다.
6. **확대 또는 중단:** 전체 비용과 품질이 정한 기준을 만족하면 적용 범위를 넓힙니다. 최신성·정답률·파싱 안정성이 악화되거나, 운영 부담을 포함한 총비용이 줄지 않으면 캐시 기간이나 적용 업무를 조정하고 필요하면 내장 검색으로 되돌립니다.

## 한계와 주의점

확인된 자료는 DoorDash 사례의 평가 데이터 구성, 비용 산정 방식의 세부 항목, 캐시 만료 기준, 검색 공급자별 가격, 실제 트래픽에서의 결과를 모두 보여주지는 않습니다. 따라서 98% 이상이라는 수치만으로 특정 조직의 절감액이나 투자 회수 기간을 예측할 수 없습니다. 모델 추론비가 제외됐다는 점도 전체 비용 판단에 반영해야 합니다.

또한 캐시 적중률, 개인정보나 내부 문서의 저장 가능 여부, 보존 기간과 접근 통제는 입력 자료에서 확인되지 않습니다. 내부 검색에 적용하려면 보안·개인정보 담당자와 저장 정책, 로그 내 민감정보 처리, 권한별 결과 격리를 별도로 검토해야 합니다. 검색 게이트웨이는 검색 결과가 정확하거나 안전하다는 보증 장치가 아니므로, 검색된 문서의 신뢰도와 후속 판단을 검증하는 절차도 필요합니다.

마지막으로 출처는 내장 검색이 최신 정보 평가에서 더 정확했던 경우와 게이트웨이 방식의 장점을 함께 전합니다. 따라서 실무 결론은 ‘검색은 반드시 분리해야 한다’가 아닙니다. 반복성이 높고 결과 재사용이 허용되며 운영 지표를 관리할 수 있는 업무에서는 게이트웨이를 시험하고, 최신성이 우선이거나 결과 활용 방식이 내장 검색에 의존하는 업무는 별도 평가를 거쳐 선택하는 것이 합리적입니다.
