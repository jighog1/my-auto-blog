## 30초 요약

OpenAI가 자체 추론 칩 Jalapeño와 AMD의 설계 작업에서 AI 모델을 활용해 회로를 개선했다고 밝혔습니다. 공개 내용에는 블록별 셀 면적 절감 추산치와 AMD 설계의 PPA 개선 결과가 포함되지만, 숫자를 곧바로 다른 칩이나 조직의 기대 성과로 옮겨서는 안 됩니다. 이 사례에서 실무자가 주목할 부분은 모델이 코드를 다시 썼다는 사실만이 아니라, 제안된 회로를 EDA 도구로 검증하고 실제 실리콘 구동까지 확인했다는 점입니다. 따라서 AI 도입을 검토할 때는 ‘얼마나 줄였나’와 함께 ‘기능이 보존됐는가, 어떤 단계에서 측정했는가’를 먼저 물어야 합니다.

## 확인된 사실

OpenAI는 Jalapeño 설계에 모델을 활용해 벡터 유닛과 행렬 유닛의 회로를 개선했다고 설명했습니다. 회사가 추산한 표준 셀 면적 감소 폭은 벡터 유닛 약 13%, 행렬 유닛 약 10%입니다. 이 수치는 전체 칩의 면적이 그만큼 줄었다는 뜻이 아니라, 해당 유닛의 표준 셀 면적에 관한 추산치입니다. OpenAI는 관련 최적화가 실제 실리콘의 초기 구동 과정에서도 확인됐다고 밝혔습니다. [OpenAI의 설계 사례 소개](https://news.hada.io/topic?id=37441&utm_source=geeknews&utm_medium=rss&utm_campaign=news)

공개된 개선 방식에는 대체 논리 구현을 탐색하고, 파이프라인 단계별 연산 분할을 바꾸며, 하드웨어 공유와 중간 저장 공간 감소를 노리는 접근이 포함됩니다. 행렬 유닛에서는 부동소수점 연산과 저정밀도 내적 회로도 다뤘습니다. 개별 연산 블록의 면적·지연 개선과 유닛 전체의 추산치는 서로 다른 범위의 결과이므로 구분해서 읽어야 합니다. [OpenAI의 설계 사례 소개](https://news.hada.io/topic?id=37441&utm_source=geeknews&utm_medium=rss&utm_campaign=news)

AMD와의 협업에서는 모델이 SystemVerilog RTL을 다시 작성해 회로 개선안을 찾았습니다. RTL은 하드웨어의 동작을 기술하는 설계 코드입니다. OpenAI는 AMD의 주력 GPU IP에서 기존 기준 설계 대비 최대 14%의 PPA 개선을 얻었다고 밝혔습니다. PPA는 전력(Power), 성능(Performance), 면적(Area)을 함께 보는 설계 지표입니다. 또한 Synopsys 도구로 각 변경이 블록의 동작을 보존하는지 검증하고, 세 지표 사이의 절충을 평가했다고 설명했습니다. AMD는 일부 변경을 제조에 넘긴 설계에 반영했고, 다른 변경은 향후 설계 파일에 추가했다고 전해졌습니다. Jalapeño는 대규모 언어 모델 추론을 겨냥해 설계한 가속기로 소개됐습니다. PyTorchKR에 정리된 설명에 따르면 OpenAI와 Broadcom은 모델 운영에서 얻은 작업 패턴을 바탕으로 추론용 칩을 설계하는 방향을 제시했습니다. 이는 회로 최적화 사례를 이해할 때 중요한 맥락입니다. 모델이 칩 설계에 쓰였다는 사실과, 모델을 구동할 하드웨어를 자체 설계한다는 사업·인프라 선택은 서로 관련되지만 같은 주장으로 취급할 수는 없습니다. ## 실무 판단

이 사례의 실무적 의미는 ‘AI가 숙련된 칩 설계자를 대체한다’는 결론보다 좁고 구체적입니다. 모델은 RTL에서 개선 후보를 만들고, 기존 검증 도구와 설계 흐름은 그 후보가 기능을 보존하는지와 PPA에 어떤 영향을 주는지 확인합니다. 즉, 성과는 생성 모델 단독이 아니라 후보 생성·검증·측정이 이어지는 작업 흐름에서 나옵니다. 공개된 설명도 Synopsys 도구를 통한 동작 보존 검증을 강조합니다. [OpenAI의 설계 사례 소개](https://news.hada.io/topic?id=37441&utm_source=geeknews&utm_medium=rss&utm_campaign=news)

둘째, 결과 지표의 범위를 먼저 확인해야 합니다. 유닛의 셀 면적 감소는 칩 전체의 전력·성능·면적 개선과 같지 않습니다. 합성 단계에서 계산한 면적, 타이밍 분석 결과, 실제 실리콘의 동작은 각각 확인하는 대상과 조건이 다릅니다. 따라서 ‘최대 14%’ 같은 수치를 내부 목표치로 바로 채택하기보다, 기준 설계와 비교 조건, 적용 블록, 검증 단계를 함께 확보해야 합니다. 이는 공개된 성과 수치가 특정 설계 맥락에 묶여 있기 때문입니다. [OpenAI의 설계 사례 소개](https://news.hada.io/topic?id=37441&utm_source=geeknews&utm_medium=rss&utm_campaign=news)

셋째, 중요한 것은 제안의 양이 아니라 검증 가능한 후보의 비율입니다. RTL 재작성은 코드가 짧아지거나 보기 좋아지는 일과 다릅니다. 동작이 달라지거나 예외 조건이 빠지면 최적화가 아니라 결함입니다. 따라서 모델이 낸 변경은 동등성 검증, 시뮬레이션, 합성·타이밍 평가처럼 조직이 이미 신뢰하는 절차를 통과해야 합니다. 이 절차를 자동화해 반복 가능한 비교를 만들지 못하면, 모델이 생성한 코드가 늘수록 리뷰 부담도 커질 수 있습니다.

## 업무에 어떻게 쓸까

칩 설계 조직이라면 처음부터 설계 전체를 모델에 맡기기보다, 범위가 제한된 블록의 후보 생성 업무부터 시험하는 편이 현실적입니다. 예를 들어 반복적인 RTL 정리나, 면적과 지연 사이의 절충을 탐색할 수 있는 블록을 선정합니다. 단, 이 선택은 권고이며 공개 사례가 특정 블록에서 같은 성과를 보장한다는 뜻은 아닙니다.

1. **대상을 좁힙니다.** 기준 RTL, 테스트벤치, 제약 조건, 기존 PPA 결과가 갖춰진 블록을 고릅니다. 기능 요구사항이 자주 바뀌거나 기준 결과가 재현되지 않는 블록은 첫 시험 대상으로 적절하지 않습니다.
2. **비교 기준을 고정합니다.** 모델이 수정하기 전 설계의 기능 검증 결과와 PPA를 저장합니다. 도구 버전, 입력 제약, 합성 조건도 함께 기록해 결과 비교가 가능한지 확인합니다.
3. **변경 단위를 작게 유지합니다.** 한 번에 여러 구조를 바꾸지 말고, 후보별로 변경 내용과 의도, 예상하는 이득을 남깁니다. 그래야 실패했을 때 원인을 좁히고, 유효한 변경만 추릴 수 있습니다.
4. **검증을 먼저 통과시킵니다.** 기능 동등성이나 프로젝트의 필수 검증에서 실패한 후보는 PPA가 좋아 보여도 채택하지 않습니다. 통과한 후보만 합성·타이밍 등 기존 지표로 기준 설계와 비교합니다.
5. **실제 적용 단계까지 추적합니다.** 후보 생성, 검증 통과, 설계 반영, 실리콘 확인을 별도 상태로 기록합니다. 합성 결과만 확인한 후보를 ‘실리콘에서 검증된 최적화’로 보고하지 않습니다.

시험 중에는 다음 조건을 미리 정해 두면 판단이 쉬워집니다.

- **계속 진행:** 기능 검증을 통과하고, 정해 둔 PPA 지표에서 기준 설계보다 나아지며, 결과를 같은 조건에서 재현할 수 있을 때.
- **보류 후 재검토:** 지표 개선은 있으나 기능 보존 검증이 끝나지 않았거나, 기준 조건이 달라 비교가 불확실할 때.
- **중단:** 요구 동작이 바뀌거나 필수 검증을 통과하지 못하는 후보가 반복되고, 검증 비용이 수작업 절감 가능성을 넘어설 때.

## 한계와 주의점

공개된 자료만으로는 각 PPA 수치의 상세한 측정 조건, 기준 설계의 전체 구성, 후보를 생성하고 검증하는 데 든 시간과 비용을 독립적으로 비교할 수 없습니다. AMD의 ‘최대’ 개선 수치는 모든 블록이나 제품에 적용되는 평균 성과로 해석할 수 없습니다. Jalapeño의 유닛별 면적 추산 역시 전체 칩 면적이나 운영 비용 절감으로 바로 환산할 수 없습니다. [OpenAI의 설계 사례 소개](https://news.hada.io/topic?id=37441&utm_source=geeknews&utm_medium=rss&utm_campaign=news)

또한 OpenAI와 협력사의 공개 설명은 실제 설계 경험을 보여주는 자료이지만, 모든 검증 데이터가 외부에 공개된 독립 평가 보고서와 같지는 않습니다. Jalapeño의 추론 전용 설계 맥락은 공개된 소개에서 확인할 수 있으나, 실제 제품의 공급 범위나 여러 워크로드에서의 장기 효율을 이 자료만으로 확정할 수는 없습니다. [PyTorchKR의 Jalapeño 정리](https://discuss.pytorch.kr/t/openai-broadcom-llm-jalapeno-feat-celestica/10925)
