## 업무에 어떻게 쓸까

처음부터 ‘내 업무 전반을 맡아줘’라고 요청하기보다, 결과와 완료 조건이 분명한 작은 과업을 고르는 것이 좋습니다. 예를 들어 회의 준비라면 자료를 모아 요약하고 질문 목록을 만드는 단계까지만 맡깁니다. 참석자에게 초대장을 보내거나 회의 내용을 외부에 전달하는 일은 별도 승인 대상으로 둡니다.

**시험 적용 단계**

1. **반복 업무를 하나 고릅니다.** 주간 회의 전 관련 이메일과 일정을 확인해 브리핑 초안을 만드는 등, 완료 여부를 사람이 판정할 수 있는 작업을 선택합니다.
2. **입력 범위를 한정합니다.** 어떤 메일함·캘린더·문서만 참고할지 지정합니다. 필요한 앱 연결이 확인되지 않거나 데이터 권한을 좁힐 수 없다면 시험을 보류합니다.
3. **산출물과 금지 행동을 함께 씁니다.** ‘요약과 다음 단계 초안 작성’처럼 결과물을 명시하고, ‘발송·삭제·게시·결제는 하지 말고 승인 요청’처럼 외부 효과가 있는 행동의 한계를 정합니다.
4. **사람이 결과를 대조합니다.** 빠진 일정, 잘못 묶인 대화, 근거가 불분명한 결론을 기록합니다. 짧은 기간 동안 오류 유형과 검토 시간을 확인한 뒤 계속 쓸지 판단합니다. 기간과 통과 기준은 조직 상황에 맞게 정해야 합니다.
5. **조건을 충족한 경우에만 범위를 넓힙니다.** 결과가 반복적으로 검토 가능하고, 권한과 승인 흐름이 명확할 때 다음 업무를 추가합니다. 문제가 생기면 자동화를 확대하지 말고 원인을 확인합니다.

복사해 쓸 요청 예시:

> 목적: 내일 회의 준비 자료를 만든다.  
> 참고 범위: 지정한 일정과 관련 이메일만 확인한다.  
> 산출물: 핵심 안건, 확인이 필요한 사실, 질문 초안.  
> 하지 말 것: 초대장 발송, 메일 답장, 문서 공유·삭제.  
> 불확실한 내용은 추정하지 말고 확인 질문으로 표시한다. 완료 후 검토가 필요한 항목을 알려준다.

이 요청 형식은 제품의 공식 템플릿이 아니라, 업무 위임의 범위와 멈춤 조건을 명확히 하기 위한 권고입니다. 실제 앱에서 이런 제한을 기술적으로 강제할 수 있는지는 별도 확인이 필요합니다.
