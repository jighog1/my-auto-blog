## 실무 판단

핵심은 ‘AI 스킬은 가치가 없다’는 문장을 문자 그대로 받아들이지 않는 것입니다. 더 유용한 해석은 스킬의 가치가 균등하지 않고, 일부는 빠르게 감가상각된다는 점입니다. 도구의 메뉴 위치, 특정 모델의 프롬프트 문법, 일시적인 우회법은 제품 업데이트만으로 효용이 낮아질 수 있습니다. 반면 업무의 목표를 정확히 정의하고, 필요한 정보를 선별하며, 결과가 맞는지 확인하고, 오류가 났을 때 책임질 사람을 정하는 역량은 특정 모델에 덜 묶입니다. 이는 자료에 적힌 직접 사실이 아니라, 기술의 제품화 가능성과 사람의 역량을 강조한 관점을 바탕으로 한 실무 해석입니다.

학습 투자를 정할 때는 스킬의 이름보다 ‘전이 가능성’을 보십시오. 전이 가능성이란 한 도구에서 배운 능력이 다른 도구나 업무에서도 쓸모 있는 정도입니다. 한 모델의 응답 형식을 바꾸는 요령은 전이성이 낮을 수 있지만, 좋은 입력 자료를 준비하고 결과를 원문과 대조하는 방법은 도구가 바뀌어도 활용될 가능성이 큽니다. 전이성이 낮은 기술을 금지할 이유는 없습니다. 다만 짧은 실험으로 효과를 확인하고, 교육 자료와 운영 문서를 계속 갱신할 수 있도록 비용을 제한하는 것이 합리적입니다.

또한 ‘빨리 도입’과 ‘늦게 도입’ 중 하나를 정답처럼 고를 필요는 없습니다. 성급한 전사 도입은 효과가 불분명한 사용법을 표준으로 굳힐 수 있고, 관망만 하면 현재 업무에서 얻을 수 있는 개선 기회를 놓칠 수 있습니다. 둘 사이의 실무적 대안은 작은 범위에서 먼저 시험하되, 조직 전체의 장기 투자와 고정 절차는 검증 뒤에 결정하는 것입니다. 즉, 실험은 빠르게 하고 표준화는 신중하게 합니다.

## 업무에 어떻게 쓸까

다음 절차를 한 업무에 적용해 보세요. 예시는 회의록 정리, 고객 문의 초안 작성, 사내 문서 검색처럼 반복적이며 결과를 검토할 수 있는 작업입니다. 기밀 정보나 개인정보가 포함된다면 승인된 도구와 입력 기준을 먼저 확인해야 합니다.

1. **업무의 기준선을 기록합니다.** 지금 걸리는 시간, 수정 횟수, 오류 유형, 최종 승인자를 적습니다. ‘더 빨라질 것 같다’는 기대만으로는 도입 효과를 판단하기 어렵습니다.
2. **AI가 맡을 범위를 좁힙니다.** 초안 작성이나 분류처럼 검토 가능한 단계부터 시작합니다. 중요한 결정을 AI에 바로 맡기기보다 사람이 승인할 지점을 남깁니다.
3. **현재 도구의 요령은 짧게 시험합니다.** 프롬프트 형식이나 설정을 바꿔 결과가 실제로 개선되는지 비교합니다. 결과가 좋아졌다면 재현 가능한 입력과 예시를 기록하되, 특정 도구에만 통하는 팁인지 표시합니다.
4. **성과와 품질을 함께 봅니다.** 처리 시간뿐 아니라 사실 오류, 누락, 수정 부담, 사용자가 검토하는 시간도 비교합니다. 시간이 줄어도 오류 검증 비용이 더 커지면 업무 개선이라고 보기 어렵습니다.
5. **정한 기간 뒤 계속·수정·중단을 결정합니다.** 재사용 가능한 효과가 확인되면 업무 절차에 반영하고, 도구 업데이트 이후 같은 시험을 다시 합니다. 개선이 재현되지 않거나 검토 비용과 위험이 커지면 해당 사용법을 중단합니다.

## 실행 체크리스트

- [ ] 교육 대상으로 삼은 기술이 특정 모델의 조작법인지, 여러 업무에 적용되는 능력인지 구분한다.
- [ ] AI를 적용할 작업과 사람이 최종 확인할 결과를 한 문장으로 정의한다.
- [ ] 도입 전 처리 시간뿐 아니라 오류와 수정 부담도 기준선으로 남긴다.
- [ ] 승인되지 않은 도구에 민감정보를 입력하지 않도록 입력 규칙을 확인한다.
- [ ] 프롬프트나 설정을 바꿀 때는 한 번에 한 요소씩 비교해 효과를 확인한다.
- [ ] 성공 조건과 중단 조건을 시작 전에 정한다. 예: 검토 시간이 늘거나 오류가 반복되면 중단한다.
- [ ] 모델이나 제품 기능이 바뀌면 기존 사용 팁이 여전히 필요한지 다시 시험한다.
- [ ] 교육 자료에 작성일과 재검토 시점을 표시하고, 오래된 요령을 그대로 표준화하지 않는다.
- [ ] 실험 결과를 공유할 때 도구 이름만 적지 말고 업무 조건과 품질 기준도 함께 남긴다.
